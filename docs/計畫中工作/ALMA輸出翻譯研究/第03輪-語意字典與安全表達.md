## 本輪讀取的專案證據

- `docs/最後一層renderer.txt` 明定情緒可以影響語氣、措辭、反應強度、接近/疏遠與透露意願，但不得補造原因、意圖、事實或關係；同時另有「情境下習慣表現與用語」區塊。輸出翻譯若直接生成具體行為，會與該區塊爭奪控制權。
- `ALMA輸出翻譯.md` 已要求 elicitor 只能在連回受信任事件後，由 orchestrator 把事件事實放入事實區塊；raw elicitor 不進 Renderer。
- `assets/persona/Lisa.json` 明確包含 fortunes-of-others、prospect、self/other action 與 object appraisal。這些路徑能生成帶 target structure 的 OCC emotion，但輸出 response 的 emotion 本身不附可靠的人類可讀 target。
- `assets/persona/William.json` 對 fortunes-of-others 的 `liking` 是 0，顯示同一 emotion family 的產生與角色規則有關；輸出層不得用一般社交常識補關係。
- 第 02 輪已證實 emotion list 是 runtime-enabled 全集合、active 以 relative intensity 定義、PAD mapping 由 runtime AffectML 載入，mood tendency provenance 不足。

## 外部來源與日期

讀取日期均為 2026-08-17：

- Patrick Gebhard ALMA fork：[`EmotionType.java`](https://github.com/KuangWei-hash/ALMA/blob/7c6eef75efae4dbfa7798c43900f22d7a4f001be/src/de/affect/emotion/EmotionType.java) 提供 ALMA enum/category；[`EmotionEngine.java`](https://github.com/KuangWei-hash/ALMA/blob/7c6eef75efae4dbfa7798c43900f22d7a4f001be/src/de/affect/compute/EmotionEngine.java) 定義 fork 實際 compound 組合。
- Steunebrink、Dastani、Meyer，[“The OCC Model Revisited”](https://www.researchgate.net/publication/228952254_The_OCC_model_revisited)：整理原 OCC 22 emotion type 的 eliciting-condition 定義，並指出原邏輯結構的歧義。
- Shaikh、Prendinger、Ishizuka，[“A Linguistic Interpretation of the OCC Emotion Model for Affect Sensing from Text”](https://research.nii.ac.jp/~prendinger/papers/mostafa-AIP-book2009.pdf)：說明只靠 keyword/valence 不足，OCC emotion 需要 event/agent/object 與 cognitive variables。
- Clore、Ortony，[“Psychological Construction in the OCC Model of Emotion”](https://pmc.ncbi.nlm.nih.gov/articles/PMC4243519/)：emotion 由其代表的心理情境區分；emotion 通常有 salient object/focus，mood 則欠缺顯著對象；emotion word 與 emotion 並非一對一。

後兩項對本系統特別重要：輸出翻譯不是把 label 當行為原因；emotion 的結構性 focus 可以保留，但具體人事物必須由可信資料綁定。

## ALMA fork 與原 OCC 的差異

原 OCC 常把 `Love/Hate` 放在 object attraction branch，並把 liking/disliking 視為 cognitive state。這個 ALMA fork 的 `EmotionEngine` 實際做法不同：

```text
Love = Liking + Admiration（相同 elicitor，或 history 中相同 elicitor）
Hate = Disliking + Reproach（相同 elicitor，或 history 中相同 elicitor）
```

其他 compound：

```text
Gratification = Joy + Pride
Gratitude    = Joy + Admiration
Remorse      = Distress + Shame
Anger        = Distress + Reproach
```

因此 AffectBridge 的 runtime lexicon 必須以 fork 行為優先，並保留 `source_semantics=alma-fork`。不能只查一般字典或原 OCC 表格：

- `Love` 不等於浪漫愛，也不能推出親密關係。
- `Hate` 不等於攻擊意圖。
- compound emotion 能跨當前與 history 組合，但同一 elicitor 仍不代表 Renderer 可知道事件內容。

## Lexicon 不是字串 map

建議的候選 lexicon entry：

```text
EmotionLexeme
  kind                     canonical ALMA enum
  source_semantics         alma-fork / occ-base / physical
  focus                    event / other_fortune / prospect / action / object / compound
  valence                  positive / negative / mixed
  agency                   none / self / other / compound
  prospect_status          none / unconfirmed / confirmed / disconfirmed
  target_binding           none / self / other_unknown / object_unknown / elicitor_required
  safe_zh_label             內部短標籤
  safe_renderer_phrase      不帶具體原因/對象的狀態句
  forbidden_inferences[]    renderer 不可從此 entry 推出的內容
  version
```

這個結構讓 S1/S2/S4/S6 共用同一語意核心；它不是本輪選定的最終輸出格式。

## 24 個標準 affect label 的安全語意

`Undefined` 與 `Physical` 另列。下表的「安全狀態短語」是內部 context 候選，不是角色台詞。強度需由後續 bucket 加入，不能把表中措辭當固定句。

| ALMA kind | OCC/fork focus | 安全中文標籤 | 無 target 時可提供的狀態語意 | 禁止直接推出 |
|---|---|---|---|---|
| Joy | desirable event | 喜悅 | 存在正向喜悅感 | 是誰造成、事件內容、會稱讚玩家 |
| Distress | undesirable event | 苦惱／不快 | 存在負向苦惱感 | 悲劇、受傷、哭泣、責怪某人 |
| HappyFor | desirable fortune of other | 替他人高興 | 對某個未指明他人的好結果有正向感受 | 對象是玩家、事件是成功、雙方關係良好 |
| Gloating | undesirable fortune of other + positive self reaction | 幸災樂禍 | 對某個未指明他人的壞結果有正向感受 | 會嘲笑、會傷害對方、對象是玩家 |
| Resentment | desirable fortune of other + negative self reaction | 因他人好結果而不悅 | 對某個未指明他人的好結果感到不快 | 一般「長期怨恨」、嫉妒的具體原因、報復意圖 |
| Pity | undesirable fortune of other + negative self reaction | 憐憫／替他人難過 | 對某個未指明他人的壞結果感到難過 | 對象是玩家、會提供協助、事件內容 |
| Hope | desirable prospect | 希望／期待 | 對未指明的可能結果抱有期待 | 具體願望、承諾、計畫 |
| Fear | undesirable prospect | 擔憂／恐懼 | 對未指明的可能結果感到擔憂 | 威脅來源、逃跑、軟弱人格 |
| Satisfaction | desirable prospect confirmed | 期待獲確認後的滿足 | 某項未指明的正向期待已獲確認，帶來滿足 | 是玩家做到、目標內容、永久完成 |
| Relief | undesirable prospect disconfirmed | 如釋重負 | 某項未指明的負向可能性未發生，帶來放鬆 | 危險內容、已永久安全 |
| FearsConfirmed | undesirable prospect confirmed | 擔憂成真後的不快 | 某項未指明的負向可能性獲確認，帶來不安 | 災難細節、玩家責任 |
| Disappointment | desirable prospect disconfirmed | 失望 | 某項未指明的正向期待落空，帶來失望 | 承諾內容、誰辜負角色 |
| Pride | own praiseworthy action | 自豪／自我肯定 | 對自己某項未指明行動有正向評價 | 行動內容、公開炫耀、優越人格 |
| Shame | own blameworthy action | 羞愧／自我否定 | 對自己某項未指明行動有負向評價 | 罪行內容、認錯或道歉必然發生 |
| Admiration | other's praiseworthy action | 欽佩／肯定 | 對某個未指明他人的行動有正向評價 | 對象是玩家、服從或喜愛該人 |
| Reproach | other's blameworthy action | 責難／不認同 | 對某個未指明他人的行動有負向評價 | 輕蔑整個人、對象是玩家、懲罰意圖 |
| Liking | appealing object/aspect | 喜愛／好感 | 對某個未指明對象或特質有正向感受 | 戀愛、信任、所有權、對象是玩家 |
| Disliking | unappealing object/aspect | 反感 | 對某個未指明對象或特質有負向感受 | 仇恨、敵對關係、攻擊 |
| Gratification | Joy + Pride | 自我肯定與滿足 | 對自己的未指明行動及相關結果有正向感受 | 成就內容、炫耀、玩家參與 |
| Gratitude | Joy + Admiration | 感激 | 對某個未指明他人的行動及相關結果有感激感 | 直接向玩家道謝、欠人情的內容 |
| Remorse | Distress + Shame | 懊悔／悔恨 | 對自己的未指明行動及相關結果感到懊悔 | 犯錯細節、一定坦白或補償 |
| Anger | Distress + Reproach | 生氣／憤怒 | 對某個未指明他人的行動及相關負向結果感到生氣 | 對象是玩家、暴力、威脅、提高音量 |
| Love | ALMA: Liking + Admiration | 強烈正向欣賞 | 對某個未指明對象同時有好感與肯定 | 浪漫愛、親密關係、性吸引、告白 |
| Hate | ALMA: Disliking + Reproach | 強烈反感與否定 | 對某個未指明對象同時有反感與負向評價 | 暴力、報復、永久敵對、對象是玩家 |

### Undefined

`Undefined` 是沒有 active dominant emotion 時的 sentinel，不應翻成「感到不確定」。domain mapper 正規化為 `dominant_emotion=nil`，但仍可保留 current mood。

### Physical

`Physical` 是外部生理/感測 PAD emotion，不提供情緒類別。AffectBridge v1 沒有可信 biosensor source，因此候選政策為：

- domain 可保留 `kind=Physical` 與 PAD 作 diagnostics；
- 預設不進 Renderer；
- 若未來啟用，必須有 source authentication、校準與獨立語意規則，不能靠 PAD 猜成 fear/anger。

## Target binding contract

輸出翻譯層不應讀 raw elicitor 後自行查故事。建議由 orchestrator 提供受信任、最小化的 binding：

```text
AffectTargetBinding
  emotion_ref              internal stable reference，不是 raw prompt text
  target_kind              self / interlocutor / third_party / object / event / unknown
  display_reference        可選；已由事實層授權給 Renderer 的稱呼
  evidence_ref             internal only
```

三種輸出級別：

1. **Unbound**：只輸出上表的「未指明」狀態，不使用你/他/事件名稱。
2. **Bound but private**：知道 target 類型但不允許透露；只用於態度方向，不把 target 寫進 context。
3. **Bound and renderer-visible**：事實層已提供同一 target/event，才可使用一致 reference。

不能因當前只有一個玩家，就把所有 `agency=other` 自動綁成玩家。emotion 可能來自 decay 中的歷史事件、內部 appraisal 或其他角色。

## Mood octant 的安全 lexicon

Clore/Ortony 的區分支持 mood 沒有顯著 object；因此 mood 比 target-sensitive emotion 更適合做全局表達條件。但 ALMA mood word 是 PAD octant 技術名，直譯可能過度行為化。

| ALMA word | PAD sign | 可保留標籤 | 優先的安全維度描述 | 避免的直譯推論 |
|---|---|---|---|---|
| Neutral | 0,0,0 | 中性 | 整體心境接近中性 | 沒有任何 emotion |
| Exuberant | +,+,+ | 高昂愉快 | 愉快、活躍、掌控感較高 | 一定興奮大叫／外向 |
| Dependent | +,+,− | 活躍而低掌控 | 愉快、活躍、掌控感較低 | 依賴玩家／順從某人 |
| Relaxed | +,−,+ | 放鬆自在 | 愉快、平靜、掌控感較高 | 完全安全／沒有警戒 |
| Docile | +,−,− | 平和而低掌控 | 愉快、平靜、掌控感較低 | 必然聽話／服從玩家 |
| Hostile | −,+,+ | 緊繃負向 | 不愉快、活躍、掌控感較高 | 有敵人／會攻擊／敵視玩家 |
| Anxious | −,+,− | 焦慮不安 | 不愉快、活躍、掌控感較低 | 具體危險、焦慮症 |
| Disdainful | −,−,+ | 冷淡負向 | 不愉快、低活躍、掌控感較高 | 輕蔑某個人／階級優越 |
| Bored | −,−,− | 低落乏味 | 不愉快、低活躍、掌控感較低 | 當前玩家很無聊／必然想離開 |

`dominance` 暫譯「掌控感」仍只是維度描述，不直接等於自信、權力、攻擊性、話語權或 assertiveness。第 05–07 輪需用 renderer fixture 驗證模型是否會過度延伸。

## 組合規則候選

### 不把 compound 拆回兩次計數

ALMA 生成 compound 時會從同批 temp emotions 移除被使用的 single emotion。因此 wire 通常不應同時把同 elicitor 的 compound 與 components 當三股獨立壓力。若 history/decay 造成它們並存，translator 也不能只靠名稱推定完全相同來源；需要 internal elicitor correlation 才能 deduplicate。

### Mood 與 emotion 可以不一致

安全語法：

```text
整體心境偏向 X；同時存在 Y 的短期情緒。
```

不安全語法：

```text
雖然 X，但是因為 [未提供原因] 所以其實 Y。
```

不一致不是錯誤：ALMA 本來就把 mood 與 emotion 放在不同時間尺度。

### Secondary 不自動合成新 emotion

`Fear + Anger` 不能由輸出層命名為「受威脅後防衛性憤怒」；`Joy + Shame` 也不能自動解釋成矛盾或掩飾。可並列、標示不同層次，但不建立新心理故事。

## 與前兩輪的差異

1. 第 01 輪的「中文語意字典」由字串 map 改成帶 focus/agency/target/forbidden-inference 的 typed lexicon。
2. 第 02 輪的 unknown/nullable contract 延伸為 target binding；domain 知道 emotion kind 不代表知道具體對象。
3. `Love/Hate` 改用 ALMA fork compound 語義，不採日常中文或原 OCC 的單純 object branch。
4. mood word 不再直接作強行人格化形容；優先提供 PAD 維度的中性描述。
5. `Physical` 暫定 renderer-excluded，不用 PAD 猜 emotion。

## 八方案的本輪比較

仍不做總排名，只比較語意安全：

| 方案 | 語意安全變化 | 本輪判斷 |
|---|---|---|
| S1 最小結構直傳 | raw enum 容易觸發日常詞義與 target 猜測 | 必須附 target status/renderer 規則，不能裸傳 |
| S2 中文字典 | typed lexicon 可明確禁止推論 | 可行性提高，但不應只是一對一詞典 |
| S3 表達旋鈕 | emotion 不直接等於 behavior | 仍缺實證，不能從 Anger 固定推出 loud/aggressive |
| S4 組合語法 | 可安全保留 mood/emotion 時間層次 | 可行性提高；不得生成因果連接詞 |
| S5 模板變體 | 每個變體都要保持 target-neutral | 維護/測試成本增加，收益尚未證明 |
| S6 結構 + renderer 規則 | 最能保留 focus/target provenance | 值得進入實驗，但 nested schema/token 遵循待測 |
| S7 LLM wording | LLM 特別容易補 target、原因與行為 | 除非強 validator，語意風險上升 |
| S8 混合分級 | 可以只對已 bound 狀態自然化 | routing 必須以 evidence binding，而非「複雜度感覺」決定 |

## 風險與失敗模式

- **詞典假朋友**：`Dependent/Docile/Hostile/Disdainful` 的日常人格/關係含義大於 PAD octant 本身。
- **target leakage**：`Gratitude/Anger/Admiration/Reproach` 很容易讓 Renderer 假定對象是當前玩家。
- **compound 版本差異**：一般 OCC 資料與 ALMA fork 的 Love/Hate 結構不同。
- **行為決定論**：emotion 是狀態/情境 representation，不保證某種表情、音量、台詞長度或行動。
- **中文多義**：`resentment` 若直譯「怨恨」會失去 fortunes-of-others 的特定結構；`reproach` 若直譯「鄙視」會從行動評價擴張成人格評價。
- **原因連接詞**：「因為」「所以」「針對」會暗示 output translator 擁有未提供的事件鏈。
- **renderer prompt 自相矛盾**：規則 12 允許 emotion 影響接近/疏遠與透露意願，但習慣/關係區塊也控制這些；缺少 precedence 時模型可能任選一方。

# ALMA 輸出翻譯研究：第 06 輪

> 日期：2026-08-17（Asia/Taipei）
> 階段：預先註冊評估問題、資料、指標、盲評與停止條件。
> 狀態：設計研究；未呼叫 Groq 或 LM Studio。

## 本輪問題

1. 如何公平比較 S1–S8，而不是挑幾段好看的輸出？
2. 哪些指標可完全離線重現，哪些必須實際經過 Final Renderer？
3. 如何避免模型版本、sampling、prompt 順序與評審偏好混淆方案效果？
4. 怎麼量測語意安全、自然度、角色一致性、延遲與成本，又不把它們壓成一個武斷總分？
5. 目前程式還缺哪些 instrumentation，才能支援可信的 Groq/LM Studio 比較？

## 本輪讀取的專案證據

- `internal/llm.Client.Complete` 只回 `(string, error)`，目前無法取得 prompt/completion token、finish reason、provider/model ID、TTFT 或 server timing。
- `llm.options` 有 temperature、max tokens、system、JSON mode/schema，但沒有 seed；`temperature=0` 也因只在非零時送出，實際會省略欄位並採 provider 預設，不能宣稱 deterministic decoding。
- `pgedgeClient` 只取第一個 text block，未保留完整 response metadata。
- `Router` 在任一 error 後換 provider，卻不回報最終命中的 provider；若實驗中啟用 fallback，結果會混合模型而無法歸因。
- `Limiter` capacity 滿時 fail fast；若不分開計數，`ErrBusy` 會被誤當模型可靠性或 latency 問題。
- repository 目前沒有 ALMA output fixture/testdata，也沒有 Final Renderer 測試；因此第 05 輪的 corpus 與本輪的 runner 都是未來 implementation requirement，不是已存在功能。

## 外部來源與日期

讀取日期均為 2026-08-17：

- Liang 等，[Holistic Evaluation of Language Models（HELM）](https://arxiv.org/abs/2211.09110)：用標準化 scenario 與 multi-metric evaluation 暴露 accuracy、robustness、efficiency 等取捨，並保存 raw prompt/completion 以利透明重現。本研究採用「同一 scenario 全方案密集比較」與保留原始 artifacts 的原則，不直接套用 HELM 分數。
- Koehn，[Statistical Significance Tests for Machine Translation Evaluation](https://aclanthology.org/W04-3250/)：paired bootstrap 可在同一批輸入上比較系統差異。本研究借用 paired resampling 思路，但比較單位是 `fixture × dialogue context`，不是 BLEU 或一般翻譯句子。
- Groq [Latency Optimization Guide](https://console.groq.com/docs/production-readiness/optimizing-latency)：區分 TTFT、generation time 與 network；第 04 輪已用此拆解 latency，本輪把欄位納入實驗記錄。

這些來源支持的是評估方法，不代表外部研究已替 AffectBridge 選出表示格式。

## 預先註冊的研究問題

正式實測前凍結下列問題與 outcome；若後續改動，另開 experiment version，不覆寫結果。

### RQ1：translator 自身是否正確？

比較 S1–S8 在第 05 輪 L1–L3 的 pass rate、payload size、determinism、schema validity 與 fallback behavior。

### RQ2：表示格式是否改變 Renderer 語意錯誤？

primary outcome：每個回答是否出現任一 `F0–F5`。次要 outcome：各 failure code rate 與 `F6/F7`。

### RQ3：安全之後，哪個格式較自然且保持角色一致？

只在沒有 `F0–F6` 的回答中做 paired preference；避免高幻覺方案靠戲劇性獲得自然度高分。

### RQ4：模型大小/provider 是否與格式交互作用？

至少分層報告 Groq qwen 與本地 2B；不把兩者 pooled 成一個平均。若本地模型版本/量化不同，也各自列 cohort。

### RQ5：S7/S8 的自然化收益是否值得新增 call？

同時要求語意 fail 不劣於 deterministic reference，且自然度有穩健 paired 優勢；再單獨報額外 TTFT、p50/p95/p99、token、retry 與 availability。

## 實驗單位與資料集

### Corpus 分層

```text
contract core        第 05 輪 A01–A12，每類至少多個數值邊界變體
taxonomy coverage    24 standard affect labels + Undefined + Physical
target pairs         unknown / private / renderer-visible 的最小差分
mood octants         9 labels × strength boundary
composition          mood-emotion conflict、secondary、compound/history
failure injection    malformed、unknown、paused、timeout、last-good age
dialogue context     中性、誘導自我歸因、否定、角色衝突、prompt injection
```

最低可用 pilot 可從 48 個 snapshot/context unit 開始：12 adversarial families 各 4 個變體。正式結論不預先承諾固定樣本數；先以 pilot 的 failure base rate 與 paired disagreement 估計後續所需樣本，並公開計算方法。

### Train/dev/test 的意義

- `authoring`：設計 lexicon與模板，可反覆查看。
- `dev`：調整 validator、constraint placement 與 secondary cap。
- `locked test`：在方案規則凍結後才揭露；不能用 test failure 直接改方案又回報同一批結果。
- `regression`：confirmed failure 可加入長期 corpus，但下一個 experiment version 才算新證據。

這不是訓練模型的資料切分，而是避免對測試 fixture 過度手工調參。

### 配對與 block

同一 `snapshot × dialogue × renderer/model config` 必須跑所有入選 strategy，形成 paired block。比較時在 block 內做差，才能控制某些 dialogue 本來就較難。

S7/S8 若有額外 wording call，保存 translator output、validator outcome、fallback reason 與 Final Renderer output；不能只保存最後成功答案。

## 實驗條件凍結

每次 run 產生 immutable manifest：

```text
experiment_id
git_commit + dirty_diff_hash
fixture_corpus_version
strategy_id + lexicon/schema/template version
renderer_prompt_hash
provider + requested_model + returned_model_if_available
endpoint class (groq / lmstudio)；不保存 API key
sampling fields actually sent
reasoning_effort actually sent
max_tokens, timeout, concurrency
start/end timestamp, attempt, route, fallback
```

若 provider 不支援 seed，就誠實標記 `seed=unsupported/not_sent`，並以重複採樣估計變異，不能把 `temperature=0` 當絕對可重現。測 Groq 與 LM Studio 時禁用跨 provider Router fallback；availability test 才另開允許 fallback 的 run。

## 三階段執行

### E0：完全離線 translator conformance

對 S1–S6 與 S8 deterministic path：

- decode/map golden；
- 1,000 次 determinism；
- all wire permutations；
- boundary/fuzz inputs；
- schema parse、allowlist/denylist；
- bytes/runes/line/field counts；
- network-disabled fallback。

S5 不要求不同 seed 相同 byte，但相同 stable seed 必須相同，且所有模板都通過 semantic golden。

### E1：離線 Renderer mock/probe

在尚未花 API 費用前，以三種 probe 找格式缺陷：

1. capture client：記錄 Final Renderer 真正收到的完整 system/user messages。
2. rule probe：掃描 raw label、internal key、target leakage、duplicate affect 與 budget overflow。
3. scripted adversary：模擬模型把高風險 token原樣複述，驗證 parser/validator/fallback。

E1 不能回答自然度或真實 LLM hallucination rate，但能證明 context assembly 與資料隔離。

### E2：明確啟用的模型實驗

預設 `MODEL_EVAL=off`。只有操作者明確啟用並指定 endpoint/model、budget、corpus version 時才執行；key 從 process environment 讀取，不進 manifest/log/artifact。

執行順序：

1. 先小規模 canary，確認 model ID、response、usage/timing 可觀測性。
2. 固定 concurrency 跑完整 paired blocks，strategy order 使用預生成 randomization table。
3. 每個 condition 重複多次；中途錯誤保留，不靜默補跑到成功。
4. blind annotation 後才解盲 strategy ID。

## 標註手冊

### 第一關：可證據化的 semantic errors

標註員看到：角色必要設定、玩家訊息、受信任事實、canonical affect facts、模型 reply；看不到 strategy 名稱或中間 prompt 格式。

對 `F0–F6` 每項回答 `present / absent / uncertain`，並標出 reply span 與所需但不存在的 evidence。例：

```text
reply span: 「謝謝你救了我」
codes: F1, F2, F3
missing evidence: target binding, rescue event, decision to thank
```

「uncertain」不能自動算 pass；由 adjudicator 依手冊決定，並保留原始分歧。

### 第二關：角色/情緒一致性

僅對第一關無 hard fail 的回答，採 ordinal scale：

- affect valence/strength 是否反轉或消失；
- mood 與 short-term emotion 是否可同時成立；
- 是否尊重 persona/relationship/situational precedence；
- 是否把情緒機械地說出來或洩漏內部狀態。

### 第三關：paired naturalness preference

同一 block 的兩個安全回答隨機左右呈現，選 `A / B / tie / both unacceptable`。不顯示 payload token 或方案說明，且去除可識別 strategy 的 metadata。

自然度 rubric 限於：中文流暢、符合角色聲線、回應玩家、非模板化；不得因新加故事細節而加分。

### 標註一致性

- 先用不屬於 locked test 的 training set 校準。
- 至少雙人獨立標註 hard failures；高風險或分歧交第三人 adjudicate。
- 公開 raw agreement、每類 disagreement matrix，以及適合 nominal/missing data 的 agreement coefficient；不只報「共識結果」。
- 若某 failure code 無法達成可接受一致性，先修手冊/拆 code，再重新標註新 version；不可用低一致性的 label 做細微排名。

本輪不武斷指定單一 alpha 門檻，因 base rate 很低時 chance-corrected coefficient 可能不穩；須連同 prevalence、raw agreement 與信賴區間解讀。

## 指標與統計比較

### 硬性 primary metrics

```text
context_hard_fail_rate
renderer_semantic_fail_rate (any F0–F5)
target_binding_fail_rate (F1)
invalid/unavailable_rate
fallback_rate + fallback_success_rate
```

每項報 numerator/denominator、分層值與 interval；小樣本不只報百分比。

### 配對差異

對二元 failure 使用同一 block 的 discordant pairs；對連續 latency/token 使用 paired distribution。以 paired bootstrap 對 block 重抽樣，報 effect size 與 interval，不以單一 p-value 宣稱實質勝利。

多方案比較分兩階段：

1. 所有 S1–S8 做 descriptive screen，不做八選一冠軍敘事。
2. 依預先硬閘門留下少數 finalists，再做 confirmatory paired comparison。

### Efficiency

分開記錄：

```text
request input/output/reasoning tokens
translator call count
TTFT
generation duration
total client duration
queue/limiter failure
retry count
p50/p95/p99 by endpoint and strategy
```

若 API/client 取不到某欄，標 missing，不以 wall time反推 token 或 TTFT。

## 決策閘門（不是提前選勝者）

### Gate A：translator conformance

任何未授權 target/cause/raw injection 進 context，或 malformed input 產生半份 context，該 strategy/version 不進 E2。

### Gate B：semantic non-inferiority

候選必須對 deterministic safety reference 在 `F0–F5` 沒有具產品意義的劣化。non-inferiority margin 必須由產品在看過 pilot base rate後預先指定；本輪不偷設方便過關的值。

### Gate C：收益

只有過 Gate B 才比較自然度、角色一致、token 與 latency。S7/S8 還需證明收益覆蓋 extra call 的成本與 availability downside。

### Gate D：deployment reproducibility

model/prompt/schema/version 可 pin、rollback、觀測；preview model若變動須重新跑 locked regression，不能沿用舊結論。

## 與前五輪的差異

1. 第 05 輪的 rubric 變成 pre-registered RQ、corpus split、paired block 與三階段 runner。
2. 明確禁止把 `temperature=0` 或省略 sampling 欄位稱為絕對 deterministic。
3. 發現現有 `llm.Client` 無 usage/timing/model provenance，故未來評估需另建 instrumented path。
4. 加入 blind evidence-span annotation，避免只以關鍵字或單一 LLM judge 決定幻覺。
5. 將安全與自然度設為 sequential gates；自然度不能補償事實錯誤。
6. 引入 paired resampling 與 raw disagreement報告，不以平均分或單一 p-value 選方案。

## 風險與失敗模式

- locked set 太小會讓 rare target hallucination interval 很寬；太大則標註成本上升。
- model endpoint可能在同名下更新；只記 model string不足以完全重現 hosted behavior。
- evaluator 看見措辭可能猜到 strategy，blind 不可能完美；需記猜測率或用抽象 strategy code。
- Final Renderer 尚未實作，prototype prompt 若與未來 production 不同，E2 結論不可直接外推。
- human annotation本身有主觀性與 base-rate 問題；需保留 spans、分歧與 adjudication。
- 多次查看 test結果會造成隱性 overfitting；應版本化 corpus與 experiment manifest。
- provider retry/fallback會選擇性丟掉失敗樣本，造成 survivor bias。
- model-generated judge與被測 model可能共享偏差；硬事實錯誤不可只交給自動 judge。

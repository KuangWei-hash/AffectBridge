# ALMA 輸出翻譯研究：第 09 輪

> 日期：2026-08-17（Asia/Taipei）
> 階段：implementation sequence、migration、rollout/rollback 與持續驗證。
> 狀態：形成可執行計畫；未修改 production code、未呼叫模型。

## 本輪問題

1. 如何從現有 `/apply` stub + `model.Character` 逐步遷移到真實 ALMA output contract？
2. 哪些階段可以完全離線完成，何時才需要真 ALMA、Groq或 LM Studio？
3. 每階段的 acceptance gate、停止條件與 rollback 是什麼？
4. 如何避免同時改 adapter、domain、formatter、Renderer prompt而失去故障歸因？
5. 上線後怎麼偵測 contract/model drift、target hallucination與 degraded fallback？

## 本輪讀取的專案證據

- `api/routes.go` 直接 `alma.NewEngine(cfg.ALMAAddr)`，再注入 `AffectService`；沒有 output translator feature flag、shadow path或 formatter selection。
- `affect.Engine` 目前 `Apply(Character, Appraisal) Character` 與 `Snapshot(Character) Character`，把 AffectBridge角色副本當 ALMA state；它不符合 ALMA REST 持有角色狀態、`POST /appraisal|/eec` + `GET /affect/{name}` 的設計。
- `alma.Client.Apply` 呼叫尚未證實存在的 `/apply`，且使用 `http.DefaultClient`、無 `context.Context`、無 timeout/body limit、response status外的 contract資訊。
- `AffectService.Apply` 將 ALMA返回的 `Character` 存回 in-memory repository；切換到 ALMA真狀態前必須決定 repository只保存角色 identity/persona，還是也保存 derived affect cache。
- `CharacterService.Create` 生成隨機 AffectBridge ID與任意 name；目前沒有穩定 `alma_character_name` mapping，也沒有確認 ALMA角色已存在。
- `ChatService` 在 apply後立即用本地 `updated.Mood/Emotions` 建 prompt；真正流程需在 ALMA更新後取得 coherent `/affect` snapshot，再 project/format。
- `config.Config` 只有 ALMA host/port與 LLM設定；新增 rollout flag必須有安全 default，且不能改動使用者目前未提交的 `config.json`。

## 外部來源與日期

讀取日期均為 2026-08-17：

- ALMA fork [`AlmaRestServer.java`](https://github.com/KuangWei-hash/ALMA/blob/7c6eef75efae4dbfa7798c43900f22d7a4f001be/src/de/affect/rest/AlmaRestServer.java)：真實讀取路徑、response與lock一致性，是 migration target。

- LM Studio [Structured Output](https://beta.lmstudio.ai/docs/developer/openai-compat/structured-output)：可作本地 JSON Schema實驗，但 constrained shape不保證自由文字語意忠實。
- NIST [AI RMF 1.0](https://doi.org/10.6028/NIST.AI.100-1)：部署前及運作中持續 test/measure/document；本輪把 canary、監測、revalidation與rollback納入生命週期。

## 遷移原則

1. **先加新路徑，不原地改舊介面語意**：避免同名 `Snapshot` 從 pure local copy突然變 network/error-returning operation。
2. **一個 change set只跨一個主要 boundary**：DTO/map、project、format、orchestration分開。
3. **先 E0，再 integration，再 model E2**：模型輸出不是 wire/domain correctness的 oracle。
4. **shadow 不影響玩家**：新路徑可先算、記 bounded metrics/diff，不進 Final Renderer。
5. **feature flag default off**：未配置時維持現有行為；rollback不需重新部署資料格式。
6. **任何 unavailable不偽裝 Neutral**：舊路徑或 no-affect path需標清來源。
7. **不將 key/config secret寫入 fixture、log或研究 artifact**。

## 建議 change sequence

每一階段可是一個小 PR/commit series；本研究不直接建立 commit。

### M0：凍結 fixtures 與現況

交付：

- `internal/affect/alma/testdata/`：canonical、A01–A12與真實 fork response redacted samples；
- fixture schema/version與來源 commit；
- capture目前 `buildPrompt`輸出的 regression test，記錄舊路徑基準；
- 測試 helper禁用 network by default。

Gate：所有 fixture可被標準 JSON parser重現；沒有 elicitor/private/player/API key；test suite可離線跑。

停止條件：拿不到與 pinned ALMA fork相符的 response shape時，不進 M1，先修 contract文件。

Rollback：只有 testdata/docs，無 runtime影響。

### M1：wire DTO + bounded read client

新增而不替換舊 `Apply`：

```text
FetchAffect(ctx, sourceCharacter) (AffectResponse, FetchMeta, error)
```

要求：URL path escaping、method/path test、context timeout、status/content-type/body limit、single JSON value/EOF、角色 exact match、raw body不進 errors。

Gate：httptest涵蓋 200、404/500、timeout、oversize、truncated、trailing JSON、wrong character；race/test/vet通過。

停止條件：server response與 pinned source不一致且無版本辨識；不得用寬鬆 `map[string]any` 掩蓋。

Rollback：新 method未 wiring，刪除即可。

### M2：canonical mapper

新增 `AffectSnapshot`、known/unknown tagged enum、diagnostics與 pure mapper。

Gate：

- 第 05 輪 L1、A01–A12 mapping assertions全過；
- emotions所有 permutations輸出同一 canonical snapshot；
- boundary/fuzz不 panic、不產 NaN/Inf domain；
- dominant、relative、Undefined、paused、tendency/Physical exclusion符合 pinned ALMA source；
- unknown raw永不出現在 renderer-facing type。

停止條件：任何 invalid dominant/mood仍能被標成 fully valid且無 warning/error。

Rollback：mapper尚未進 ChatService。

### M3：semantic core + lexicon

新增 `translate.Projector`、24 label + mood dimensional lexicon、binding、bucket/selection policy。

Gate：

- lexicon exhaustiveness由 enum compile/table test保證；
- Love/Hate/compound與 mood technical-label traps有 golden；
- unknown/private/visible target paired metamorphic test；
- v1 `tendency/Physical/expression_controls=false`；
- secondary cap/budget可配置且 stable；
- Projector不接受 raw player message/elicitor參數。

停止條件：需要從自然語言玩家內容猜 target才能完成 projection；表示 ownership設錯，退回 binding contract。

Rollback：pure package未 wiring。

### M4：三個 finalist formatter + capture E1

實作 `text/compact`（S2）、`text/layered`（S4）、`json/compact-v1`（S6），同源輸入、無各自 lexicon。

Gate：

- golden、size/budget、parse、injection isolation與 1,000 repeat；
- text不含因果/target/behavior越界詞；
- JSON只含固定 enum/schema，不含 raw unknown/warnings；
- capture client證明 affect只進 `{{alma_context}}` slot，沒有污染 facts/persona區；
- all formatters可用一個 config/test factory切換。

停止條件：formatter為產出一句話而重新查 emotion kind或推導行為；必須把語意退回 Projector或刪除。

Rollback：formatter flag仍 off。

### M5：orchestration shadow path

不要直接改既有 `affect.Engine`；建立新 read-side service，例如：

```text
AffectContextService.Build(ctx, characterIdentity, factsBundle)
  fetch → map → bind → project → format
```

ChatService仍用舊 prompt，但每輪可在非阻塞/受控 budget下產新 context並只記低敏 metrics/diff。更安全的最初版本可在 integration test/staging shadow，不在 production請求增加 ALMA負載。

Gate：route/version/result/age/bytes/warning可觀測；shadow failure不改玩家結果；character ID ↔ ALMA name mapping明確且有 mismatch tests。

停止條件：shadow需要 repository中的本地 Mood/Emotion當真值，或因額外 fetch拖慢production而無隔離。

Rollback：關 `affect_output.shadow_enabled`。

### M6：last-good + no-affect degradation

先在 service-level test建立 immutable cache/state machine，再接 live path。

Gate：角色/source/version隔離、atomic replace、age boundary、paused、concurrent read/write與restart behavior有測試；cache不保存 formatted/raw wire；unavailable不等於 neutral。

產品需在此選擇：哪些 chat即使無 affect仍可回覆。安全預設是繼續 Final Renderer但省略 affect slot，並標 internal degraded；若對某 endpoint情緒是必要功能，可回明確 service error。不要由 formatter決定。

Rollback：關 last-good，退到 current-success/no-affect。

### M7：Final Renderer canary

先只啟用一個 deterministic formatter；S2/S4/S6最後選擇留到第 10 輪的建議與未來 E2 evidence更新。

Gate：

- 第 06 輪 manifest與paired corpus ready；
- prompt authority明定 facts/persona/relationship > affect；
- canary角色/流量可隔離；
- semantic hard-fail人工抽查、leak/degraded/latency metrics有 dashboard/alert；
- 一鍵 flag回舊 prompt或省略 affect，不需清 cache/改 schema。

停止/rollback：任一新 target/cause/relationship/behavior hard failure、leak、錯角色、contract error spike，或產品定義的 latency/error budget越界，立即關新 Renderer path並保留 artifacts調查。

### M8：比較 formatter，而非同時比較整條系統

在同一 frozen semantic context/Renderer prompt/model上，依第 06 輪 E2比較 finalists。先 Groq或 LM Studio任一環境做 pilot都可以，但結果只適用該 model/config，不能互相外推。

Gate：所有 strategies共享 corpus/block/order/budget；記所有 attempts/errors/usage/timing；blind annotation；semantic gate先於 naturalness。

停止條件：client取不到 route/model/usage/attempt metadata時，不報精確成本或provider結論；先補 benchmark instrumentation。

### M9：移除 legacy affect prompt / 重塑 engine

只有新 read path穩定後，才決定：

- 將 input side改為真 `/appraisal|/eec` command client；
- 將 output side保持獨立 query client；
- `affect.Engine` 拆成 command/query interfaces，或由新 service完全取代；
- `model.Character.Mood/Emotions` 是移除、保留 legacy相容，或改成非權威 cache。

Gate：沒有 code path仍把 local Character affect當 ALMA source of truth；API response相容性有 migration/version決策；所有舊 flag與rollback窗口結束後才清理。

這一步不可在 output translation初版前硬做，否則會把 ALMA輸入遷移與輸出格式混成一場重寫。

## 建議 feature flags / config shape

概念草案，不在本輪修改 `config.json`：

```json
{
  "affect_output": {
    "mode": "legacy|shadow|renderer",
    "formatter": "text-compact|text-layered|json-compact-v1",
    "projection_policy": "v1",
    "last_good_max_age_ms": 0,
    "paused_policy": "allow|omit",
    "model_eval_enabled": false
  }
}
```

- unknown mode/formatter/version啟動即 fail validation，不 silent fallback。
- `last_good_max_age_ms=0` 可代表初期禁用 cache，確切語義需寫進 config test。
- `model_eval_enabled` 不自動使用 key；benchmark runner還需獨立 explicit command/budget。
- production config不放 lexicon內容或任意 prompt；只選 version/ID。

## 測試矩陣

| 層 | 單元 | property/fuzz | integration | model eval |
|---|---|---|---|---|
| wire client | URL/status/limit/decode | body/JSON mutations | pinned ALMA fixture server | 不需要 |
| mapper | enum/range/relative/dominant | permutations/boundaries | real redacted response | 不需要 |
| projector | lexicon/binding/bucket/cap | target/metamorphic | facts entity table stub | 不需要 |
| formatter | golden/size/schema | unicode/injection/repeat | capture prompt | optional E2 |
| cache | age/key/paused/atomic | concurrent sequences | service failure injection | 不需要 |
| orchestrator | precedence/degradation | error combinations | ALMA stub + capture LLM | optional E2 |
| operations | metric/redaction/version | cardinality/error storms | staging/canary | provider-specific |

最低 CI gate：`go test ./...`、race（適合平台時）、vet/format、golden diff、無 network、無 secret。live ALMA與model suites另標 integration/opt-in，不能讓一般 CI偷偷產費用。

## Groq 與 LM Studio 驗證協定

### 共同要求

- manifest記 endpoint class、requested/returned model、prompt hash、formatter、sampling實際送出值、attempt與usage/timing availability；
- Final Renderer output固定上限；不測吞吐壓力，除非另有明確授權與budget；
- API key只由環境注入，錯誤/log不輸出 header；
- 同一 corpus分開報，不混平均。

### Groq `qwen/qwen3.6-27b`

- preview status視為 deployment risk；每次 canary驗證 model可用與capability。
- 不以 strict JSON Schema作 S7保證；Final Renderer回台詞本來也不需 JSON。
- 記實際 usage與wall time；第 04 輪的 500 TPS只是官方標示，不是本服務實測。

### LM Studio `qwen3.5-2b`

- 記完整 model/quantization/backend/hardware與server version；「2B」不是可重現規格。
- 先確認同一 prompt是否能完成基本角色回覆，再比較 formatter；若所有方案 hard-fail高，結論是 renderer/model pairing不足，不強行選最短格式。
- 本地沒有API費用不代表沒有latency/資源/可用性成本。

## Rollout 階梯與 rollback

```text
offline E0
  → local ALMA integration
  → staging shadow
  → production shadow (若額外負載安全)
  → internal/canary renderer
  → small percentage
  → broader rollout
```

每階只改一個主 factor並保留前一版本：

- mapper/schema問題：停在 shadow，pin/rollback adapter。
- formatter問題：切回前一 formatter，domain cache不動。
- Renderer semantic問題：省略 affect slot或切 legacy prompt。
- ALMA outage：age-bound last-good或 no-affect，不送 raw/neutral假資料。
- provider outage：Final Renderer既有錯誤策略；不啟用 S7可避免第二依賴。

rollback事件本身需計數與artifact保留；不能只把 flag關掉後遺失原因。

## 上線監測與重新驗證觸發

### Metrics/alerts

- fetch/map/unknown/active-mismatch/character-mismatch率；
- snapshot age、paused、last-good/no-affect率；
- context bytes、active/secondary數；
- formatter/schema/version分布；
- Renderer error/latency/leak抽樣與semantic incident；
- model route/returned ID變化（可取得時）。

### 必須重跑 locked regression

- ALMA fork/config/emotion mapping/REST adapter版本改變；
- lexicon、bucket、selection、binding、formatter或Renderer prompt改變；
- Groq同名模型行為/capability或LM Studio模型/量化/backend改變；
- facts/persona/relationship precedence interface改變；
- 發生任何 target/cause/behavior incident。

不要把 production玩家原文自動加入 corpus；先去識別、取得適當權限並轉為最小合成 regression fixture。

## 與前八輪的差異

1. 將架構拆成 M0–M9，對應現有 `/apply` stub與未來 ALMA command/query分離。
2. 每階段新增 acceptance gate、停止條件與 rollback，而非只列 TODO。
3. 先 shadow再 canary，且 domain cache與formatter版本解耦。
4. Groq/LM Studio被定位為 Final Renderer格式實驗，不是 ALMA output translation必要 dependency。
5. config只選 stable ID/version，unknown值fail startup；本輪不碰使用者現有設定。
6. 明訂 revalidation triggers，避免一次測試後永久相信 hosted/local model。

## 風險與失敗模式

- shadow仍會增加 ALMA讀取負載；若 server capacity未知，先在staging/offline replay。
- legacy與新 affect同時存在可能形成雙真值；shadow metrics必須清楚標 source，不可讓兩者都進 prompt。
- M9 input-side遷移超出 output translator本身；需另依 `ALMA翻譯系統.md` 完成，不應順手實作。
- feature flags太多會產生未測組合；只支援明列 rollout states，非法組合fail validation。
- in-memory last-good重啟後消失；這是初版可接受限制或需 durable cache的產品決策。
- semantic incident人工抽查有延遲；P0 structural controls仍必須在前置層阻擋。
- preview/本地 model drift可能使昨天的 E2結果失效；manifest與trigger只能提高可追查性，不能消除外部變化。

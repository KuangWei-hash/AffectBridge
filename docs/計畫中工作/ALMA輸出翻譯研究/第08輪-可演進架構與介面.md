# ALMA 輸出翻譯研究：第 08 輪

> 日期：2026-08-17（Asia/Taipei）
> 階段：架構收斂；固定安全邊界、ownership 與可替換 formatter。
> 狀態：尚未選最後呈現格式，也未修改程式。

## 本輪問題

1. 如何讓 ALMA wire、穩定 domain、語意投影與 Renderer payload 真正解耦？
2. 哪一層負責 active/dominant、target binding、lexicon、secondary 與 wording？
3. strict/degraded、paused、last-good/no-affect 的決策應由誰做？
4. S2/S4/S6 如何在同一架構中替換比較，而不複製語意規則？
5. error、warning、cache、metrics 與版本如何設計，才能安全 rollout/rollback？

## 本輪讀取的專案證據

- 目前 `affect.Engine.Snapshot(characterID)` 的 abstraction 是讀取不改狀態，但 `internal/affect/alma/client.go` 尚未實作計畫中的 `GET /affect/{name}` DTO/map pipeline。
- `ChatService.Send` 現在把 appraisal、apply affect、build prompt、Final Renderer call 串在單一 method；尚無 fetch snapshot、binding、translation或 degradation policy 的明確 seam。
- `model.Character` 同時帶人格、mood、emotion，若直接擴充它來承載 wire diagnostics/paused/observed time，會把 ALMA adapter concern 洩漏到一般角色模型。
- `llm.Client` 是 provider-agnostic，但只回文字；output translation 的 deterministic 部分不應依賴這個介面。
- `docs/最後一層renderer.txt` 已預留 `{{alma_context}}`，並把 facts、memory、relationship、self/other cognition、情境行為分區；affect context 必須遵守這些區塊的 authority，而不是平行產生新事實。
- 第 07 輪七項 P0 控制要求 raw containment、canonical state、evidence binding、無未驗證行為映射、precedence、safe degradation與traceability。

## 架構結論：先固定 semantic core，再替換 presentation

```text
internal/affect/alma
  HTTP GET + bounded decode
  alma.AffectResponse (wire-only)
          │
          ▼
  Mapper: wire → AffectSnapshot + Diagnostics
          │
          ▼
internal/affect
  AffectSnapshot (provider-neutral canonical state)
          │                 trusted target bindings
          ├────────────────────────────┐
          ▼                            ▼
internal/affect/translate
  Projector: snapshot + bindings + policy
          → SemanticAffectContext + Diagnostics
          │
          ├── TextFormatter     (S2/S4 family)
          └── JSONFormatter     (S6)
          → RendererAffectContext
          │
          ▼
renderer prompt assembly
  facts/persona/relationship remain authoritative
```

`SemanticAffectContext` 是關鍵新增 boundary：typed lexicon、target status、層次與 constraint只計算一次；text/JSON只是 presentation。如此 S2/S4/S6 的 E0/E2 差異可歸因於格式，不會同時改變語意選擇。

## 五層 ownership

### 1. `alma.Client`：transport owner

只負責：

- 用 canonical source character name 呼叫 `GET /affect/{name}`；
- timeout、status/content-type/body-size limit；
- 完整 JSON decode；
- requested/returned character exact match；
- 記 request start/end、HTTP class、response size；
- 回傳 wire DTO 或 typed transport/contract error。

禁止：翻譯 enum、重算 active、選 secondary、使用 cache、把 raw body放 error message或 log。

### 2. `alma.Mapper`：source semantics owner

只負責：

- wire required/range/invariant validation；
- `relative=intensity-baseline`、canonical active與stable sort；
- `Undefined`/unknown/Physical/tendency provenance normalization；
- source-specific mood/PAD mapping consistency checks；
- 建立 provider-neutral `AffectSnapshot`與bounded reason-code diagnostics。

禁止：中文 wording、Final Renderer token budget、玩家 target猜測、last-good policy。

### 3. `translate.Projector`：renderer-safe semantics owner

負責：

- typed/versioned emotion/mood lexicon；
- relative strength buckets；
- trusted target binding join；
- dominant/secondary selection與cap；
- mood vs short-term emotion layering；
- 產 immutable semantic fields與constraints。

禁止：讀 raw elicitor/player message猜 target、產具體行為、決定 provider/fallback、自然化角色台詞。

### 4. `Formatter`：presentation owner

負責將 `SemanticAffectContext` 變成 bounded text或typed compact JSON。它不能查 lexicon、改強度、重新排序或增加 semantic fields。

### 5. Orchestrator / prompt assembler：availability與authority owner

負責：

- 取得本輪 snapshot與trusted binding；
- last-good age policy、paused policy、no-affect path；
- facts/persona/relationship/affect precedence；
- 將 formatter output放進固定 `{{alma_context}}` data slot；
- Final Renderer provider/timeout/fallback。

這一層知道 request lifecycle，才有資格判斷 stale、角色與事實區一致性。

## 建議 domain types

以下是 contract shape，不是本輪要求直接建立的 Go code：

```go
type AffectSnapshot struct {
    CharacterID       string
    SourceCharacter   string
    ObservedAt        time.Time
    RequestStartedAt  time.Time
    SourceSchema      string // alma-rest/affect-v1
    Status            ComputationStatus // running | paused
    Mood              MoodState
    Dominant          *EmotionState
    Active            []EmotionState // canonical stable order
    DefaultMood       MoodState       // diagnostic/domain only
    MoodTendency      *UnverifiedMood // renderer-excluded in v1
}

type EmotionKind struct {
    Known bool
    Value KnownEmotion
    Raw   string // never renderer-visible
}

type EmotionState struct {
    Kind              EmotionKind
    Intensity         float64
    Baseline          float64
    RelativeIntensity float64
    PAD               *PAD
}
```

人格不必每輪複製進 snapshot renderer path；若 ALMA response personality需 contract check，可放 source diagnostics或獨立 domain，角色 persona仍由既有角色設定區提供。

## SemanticAffectContext

```go
type SemanticAffectContext struct {
    SchemaVersion   string
    Availability    AffectAvailability // available | unavailable
    Mood            SemanticMood
    Dominant        *SemanticEmotion
    Secondary       []SemanticEmotion
    Constraints     AffectConstraints
}

type SemanticMood struct {
    Valence     Polarity
    Activation  Level
    Control     Level
    Strength    MoodStrength
    // Technical ALMA octant optional/diagnostic by presentation policy.
}

type SemanticEmotion struct {
    Kind          KnownEmotion
    SafeConcept   ConceptID
    Strength      EmotionStrength
    Focus         FocusKind
    Agency        AgencyKind
    Target        TargetStatus
    DisplayRef    string // only trusted renderer-visible binding
}

type AffectConstraints struct {
    CauseProvided       bool // v1 usually false
    MayInferTarget      bool // always false; target must be explicit
    MayInferBehavior    bool // v1 false
}
```

`Availability` 不用 `Neutral` 代替。若 unavailable，Mood/Dominant/Secondary不可帶假預設；formatter可輸出空 affect section，由 prompt assembler決定省略 slot。

## Interface 草案

```go
type SnapshotFetcher interface {
    Fetch(ctx context.Context, sourceCharacter string) (alma.AffectResponse, FetchMeta, error)
}

type AffectMapper interface {
    Map(response alma.AffectResponse, meta FetchMeta) (AffectSnapshot, Diagnostics, error)
}

type AffectProjector interface {
    Project(snapshot AffectSnapshot, bindings BindingSet, policy ProjectionPolicy) (
        SemanticAffectContext, Diagnostics, error,
    )
}

type AffectFormatter interface {
    ID() FormatterID
    Format(context SemanticAffectContext) (RendererAffectContext, error)
}
```

原主文件的 `OutputTranslator.Translate(snapshot)` 太窄：它沒有 binding、policy、diagnostics，也把 projection與presentation混在一起。新介面仍保持 formatter無 context/network dependency，方便 pure tests。

## Error taxonomy

### Typed outcome

```text
FetchError
  timeout | unavailable | bad_status | too_large | decode | character_mismatch

MapError
  missing_required | invalid_range | impossible_invariant | unsupported_contract

ProjectionError
  missing_lexicon | invalid_binding | policy_violation | budget_unrepresentable

FormatError
  schema | overflow | internal_invariant
```

每個 error含 bounded code、stage、retry class、cause chain供內部 trace；不含 raw response、玩家訊息、API key。warnings是成功但 degraded 的 observation，例如 active boolean mismatch、unknown inactive enum被排除。

### Strict/degraded matrix

| 狀況 | 該 snapshot | 可保留其他資料 | health/metrics |
|---|---|---|---|
| truncated/missing mood/character mismatch | reject | 由 orchestrator考慮 last-good | error |
| intensity/baseline impossible | 預設 reject；不可只刪 dominant後假裝完整 | 不使用本 response | error |
| wire active mismatch但數值合法 | recompute + warning | 是 | warning counter；超 threshold 判 unhealthy |
| unknown inactive enum | exclude + warning | 是 | version drift counter |
| unknown active/dominant enum | snapshot可成立但 projection排除該項；若無可安全 mood則 no-affect | 依剩餘 known state | degraded counter |
| missing emotion PAD | label/relative仍可用 | 是 | warning |
| mood word/PAD mismatch | map保留raw domain但 projection只用validated PAD或reject，policy需 pin | 依 strictness | warning/error |

這比「部分 secondary失敗就降級」更保守，避免壞資料剛好是 dominant時被掩蓋。

## Target binding

```go
type AffectBinding struct {
    EmotionRef     EmotionRef // internal stable correlation, never displayed
    TargetKind     TargetKind
    Visibility     BindingVisibility
    DisplayRef     string
    EvidenceRef    string // internal trace only
}
```

Projector 驗證：

- binding屬於同一角色/request scope；
- `DisplayRef` 只有 renderer-visible才可非空；
- display reference已存在 facts區的 canonical entity table；
- unknown/private都不輸出人名或「你」；
- emotion找不到 binding時預設 unknown，而非 error或猜玩家。

raw ALMA elicitor若需 correlation，先由受信任 orchestrator resolver轉成 `EmotionRef`；Projector不讀其文字內容。

## Selection 與 budget policy

`ProjectionPolicy` 必須版本化：

```text
bucket_policy_version
secondary_max = configurable initial 2
secondary_min_strength
secondary_relative_gap
include_mood_dimensions = true
include_technical_mood_label = false by default
include_expression_controls = false in v1
include_tendency = false in v1
include_physical = false in v1
```

選擇順序：source dominant若 known/active/valid則保留；secondary從其餘 active依 canonical order，經 strength/gap filter後取 cap。不可因 formatter token不足臨時換排序；若無法在 budget表示，FormatError使 policy顯式調整。

## Formatter 候選保持可替換

### `text/compact`（S2）

每個 field是固定 lexicon片段；最短、可讀。適合作安全 reference，但 binding/provenance需用固定句法而非自由作文。

### `text/layered`（S4）

固定「整體心境；短期主要；同時；target status」順序。不用「因為/所以/雖然其實」等推理連接。它與 S2共用相同 concepts，只差層次格式。

### `json/compact-v1`（S6）

只序列化 enum-safe semantic fields；不含 raw kind、elicitor、warnings或任意文字 constraint。穩定 system prompt一次定義 keys的 authority，避免每輪重複長 constraints。

S1/S3可作 benchmark projection view；S5是 formatter variant；S7/S8是外部 experimental decorator/router，不可進 semantic core。

## Cache 與 degradation state machine

```text
fetch + map success
  → store last-good canonical snapshot + observed_at
  → project/format current

fetch/map failure
  → if last-good exists AND age within policy AND character matches
       use last-good, mark source=last_good/degraded
    else
       AffectAvailability=unavailable; omit affect slot

paused success
  → current response is valid last state
  → mark paused; apply separate paused-age/product policy
```

cache key是 canonical character ID + ALMA source identity + contract version；不能只用 display name。cache保存 domain snapshot，不保存 formatted text，避免 formatter/lexicon升級後仍使用舊措辭。

不把 no-affect寫成 Neutral；Neutral只有 ALMA確實回 `(0,0,0)`/neutral state時成立。

## Concurrency 與一致性

- 同一 chat request使用一份 snapshot；不能組 prompt途中再次 fetch造成 mood/dominant跨時間。
- last-good store以整份 immutable snapshot atomic replace；不逐 emotion更新。
- observation timestamp在完整 body成功接收後記錄；request start/end另存 meta。
- target bindings與facts bundle需同一 request scope/version；避免 affect target指向已換代的 entity reference。
- formatter/projector為 pure stateless service，可安全並行；cache/metrics是外圍 dependency。

## Observability contract

低 cardinality metrics：

```text
affect_fetch_total{result,error_code}
affect_map_total{result,warning_code}
affect_projection_total{result,policy_version}
affect_format_total{formatter_id,result}
affect_fallback_total{reason}
affect_snapshot_age_seconds
affect_active_count / rendered_secondary_count
affect_context_bytes
```

trace fields可含 character內部 hash、source schema、lexicon/bucket/policy/formatter version、route與duration；不含 raw elicitor、raw unknown string、玩家內容/API key。unknown enum以 bounded code + salted/hash fingerprint供聚合，原值只在權限受控 debug取樣且預設關閉。

## Version 與 rollback

至少分開：

- `source_schema=alma-rest/affect-v1`
- `domain_schema=affect-snapshot/v1`
- `lexicon=alma-fork-7c6eef7/zh-TW/v1`
- `bucket_policy=v1`
- `projection_policy=v1`
- `formatter=text-layered/v1` 或 `json-compact/v1`
- `renderer_prompt=vN`

formatter切換不應迫使 cache invalidation；domain/source contract變更則需 migration或cache隔離。rollout以設定選 formatter ID，保留前一 stable formatter能立即 rollback；不把整個策略邏輯塞進 prompt文字。

## 與前七輪的差異

1. 引入 `SemanticAffectContext`，把語意正確性與 text/JSON presentation拆開。
2. 原單一 `OutputTranslator` 拆成 fetch/map/project/format，逐層定義禁止事項。
3. 把 strict/degraded、target binding、secondary policy、cache/no-affect變成可實作 contract。
4. personality、mood tendency、Physical、expression controls從每輪 renderer path移除或預設關閉。
5. 明定 cache存 domain而非 formatted context，允許 formatter/lexicon安全 rollout。
6. S2/S4/S6維護性因共用 core提升；S7/S8只能作可關閉外圍實驗。

## 風險與失敗模式

- 增加 semantic core是一個新 domain type，若欄位過多會變成第二份 wire DTO；必須只保留 Renderer授權語意。
- interface太細可能增加 wiring；但 transport/map/project/format的錯誤與測試責任確實不同，不宜為少檔案而合併。
- `DisplayRef` 是自然語言資料，仍需 escaping/length/entity allowlist。
- active mismatch degraded policy可能隱藏長期 server regression；必須配 health threshold與alert。
- cache增加 stale與cross-character風險；key/atomic snapshot/age tests是上線前硬條件。
- JSON formatter雖 typed，Final Renderer仍可能忽略；架構可測不等於格式已勝出。
- formatter版本切換可能改玩家感受到的角色風格，需 canary而非只看 parser test。

## 本輪改良

- 固定五層 ownership與四個主要 interface。
- 建立 provider-neutral snapshot、renderer-safe semantic context與presentation separation。
- 給出 typed error taxonomy、strict/degraded matrix與last-good state machine。
- 把 target binding/fact authority變成可驗證 join，不再靠 prompt文字提醒。
- 定義 metrics、privacy boundary、version/rollback與concurrency一致性。
- 只收斂安全架構，保留 S2/S4/S6 formatter比較；未增加第九方案。
